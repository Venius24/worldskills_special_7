# Belle Croissant Lyonnais — учебный BI дашборд, Session 7

Статический HTML дашборд по пяти демонстрационным CSV из `belle_croissant_bi/data`. В нём четыре вкладки и восемь графиков: отзывы, социальные сети, сайт и история баллов лояльности. Данные готовятся локальным скриптом `build_dashboard_data.py` и сохраняются в `dashboard-data.js`; браузер не отправляет CSV на сервер.

## Открыть дашборд

Откройте `BelleCroissantLyonnais_Dashboard.html` в современном браузере. Для графиков нужен доступ к CDN Plotly при загрузке страницы; без него числовые карточки показываются, а графики заменяются сообщением. Для полностью автономного использования потребуется отдельно предоставить локальную копию Plotly.

После изменения CSV пересоберите снимок и проверьте его:

```powershell
python build_dashboard_data.py
python build_dashboard_data.py --check
```

Скрипт использует только стандартную библиотеку Python. Он проверяет уникальность ID клиентов и ссылки из отзывов и истории лояльности на клиентов. Последний баланс определяется по дате и ID транзакции; «позитивные» означает оценки 4–5, без анализа текста. Вовлечение = лайки + репосты + комментарии. `UniqueVisitors` суммируется по строкам CSV и поэтому **не** является числом уникальных людей за весь период.

## Источники и SQL

- `customers_data.csv` — 15 строк клиентов;
- `customer_feedback.csv` — 30 отзывов;
- `social_media_engagement.csv` — 30 постов;
- `website_analytics.csv` — 40 записей страниц;
- `loyalty_program_history.csv` — 60 транзакций.

В `belle_croissant_bi/sql` лежат схема и проверочные SQL запросы как отдельные учебные материалы. Схема написана для MySQL-подобного диалекта; автоматической загрузки CSV в SQL базу в этом репозитории нет. Дашборд SQL базу не читает.

Файл `Session7_DatabaseCredentials.txt` раньше отслеживался Git. Локальная копия сохранена, но исключена из нового index. Если там были действующие реквизиты, владельцу нужно вручную заменить их до публикации; удаление из index не удаляет прежние версии из истории.
